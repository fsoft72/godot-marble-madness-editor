# Marble Madness Godot Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the Three.js level editor in `~/dev/games/marble-madness` to a standalone Godot 4.6 scene (phases 1 and 2 of the spec: editor core and polish).

**Architecture:** Level data lives in plain `Dictionary` blocks (same keys as the web JSON) wrapped by `LevelData`. Pure-logic scripts (data, surface height, history, IO) are unit-tested headless. A `LevelView` node builds one `MeshInstance3D` + `StaticBody3D` per block from `BlockMeshBuilder`, rebuilding only changed blocks. Editor tools mutate `LevelData` through `History` snapshots and ask `LevelView` to rebuild. UI is `Control` nodes built in GDScript.

**Tech Stack:** Godot 4.6 (`/home/fabio/bin/godot`), GDScript, headless script test runner (no extra addons). Node.js only for one-off golden-data generation from the JS source.

**Spec:** `docs/superpowers/specs/2026-11-01-marble-madness-godot-port-design.md`. Source reference: `~/dev/games/marble-madness` (`js/main.js`, `js/geometry.js`, `js/textures.js`, `js/level01Preset.js`, `work/data/level01.png`).

## Global Constraints

- Godot 4.6, GDScript, project root `/home/fabio/dev/godot/marble-madness-editor`.
- Code, comments, identifiers in English. Constants UPPER_CASE. Early-exit conditions at the top of functions. Every function has a comment; public ones use `##` doc comments. Never use the long dash character; use `-`.
- No external art assets for the level: geometry and textures are generated by code. Only `level01.png` (tracing overlay) is copied in.
- JSON format: `{ "version": 1, "cols": int, "rows": int, "blocks": { "bx,bz": block } }`. Loader is tolerant: missing block fields get `BlockData.defaults()`, unknown keys are kept and ignored, missing `cols`/`rows` default to 14. Round trip is semantic, not byte-identical.
- Grid square, fixed per level, default 14x14. No resize UI. "Clear" empties and keeps size.
- Desktop only; JSON import/export through `FileDialog`.
- Collision comes from the same generated mesh as the visual (per block `ConcavePolygonShape3D`).
- Update `CHANGES.md` in every task; commit per task with a plain message (no attribution lines, no `--no-verify`).
- Test command: `godot --headless --path . -s res://tests/run_tests.gd` (exit code 0 = all pass).

## Review Focus

1. JSON missing `cols`/`rows`, missing block fields, or extra unknown keys: loads with defaults, nothing crashes (Task 2).
2. Invalid JSON text or wrong top-level type: error returned, current level untouched (Task 2).
3. Block with `isVoid: true` or missing cell: no mesh, no collider, no picking hit (Task 8).
4. Undo/redo after load, clear and paint; a new action clears redo; undo on empty stack is a no-op (Task 3, Task 10).
5. Paint click outside the grid or on the UI: ignored, no snapshot pushed (Task 10).
